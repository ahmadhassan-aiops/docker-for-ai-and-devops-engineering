# 26. Introduction to Docker Networking

Docker networking concepts are important because they become the foundation for Kubernetes, where networking is more complex.

## Virtual Library

- The virtual library comes from the base OS (e.g. Ubuntu) and is shared.
- The Docker engine plays the role of moving the library from the host OS to the container.
- Example: virtual library → host OS → 2 containers

## Networking Models

| Platform | Model |
|---|---|
| Docker | **CNM** (Container Network Model) |
| Kubernetes | **CNI** (Container Network Interface) |

Networking products: Calico, Weave, etc.

## CNM Components

CNM has 5 main components: Docker Engine → Libnetwork → CNM communication.

| Component | Role |
|---|---|
| **IPAM driver** | Works like DHCP, with 2 roles: (1) creating the IP pool, (2) allocating IPs from the pool |
| **Network driver** | Creates/deletes networks and adds/removes allocations |
| **Network** | NAT, bridge, host |
| **Network sandbox** | Routing between two or more containers; IP management |

## Docker Network Drivers

1. **None**: no IP is assigned with this driver.
2. **Host**: host-to-host communication; there is no NAT.
3. **Bridge**: the container communicates with the host machine using NAT.
   - a. Default → `docker0`
   - b. User-defined → you can create a network with your own name

| Item | Address |
|---|---|
| Host machine | 192.168.1.1 |
| Container | 172.17.0.1 |
| `docker0` | Gateway (NAT) |
