# 12. Docker Volume Types Hands-On

## Summary

1. An IT company develops code.
2. The developed code is containerized (Docker, Kubernetes).
3. To run an application from scratch locally, you install packages and open ports.
4. Writing your own Dockerfile is a key skill — that's why companies hire you.
5. Docker images → policies must be applied → every company uses a registry → Docker Hub (private).
6. Pulling a Docker image lets you run the container.
7. Changing the application port → container/host port → use ENV variables when running Docker.
8. Docker data persistence → data is saved permanently to a shared or local drive:
   - a. Docker volume
   - b. Bind mount
   - c. tmpfs

## Anonymous Volume

```bash
docker run -it --name container1 -v /my_storage alpine /bin/sh
```
The storage is not created at a path you choose on the host; it lives in Docker's area.

- Default path: `/var/lib/docker`
- Mapped path: `/var/lib/docker/volumes/3366c1fe14ec42ba976237f222eb5e193bb1833f7f88b0b2bbf4968a289a7649/_data`

```bash
docker volume --help
```

## 1. Docker Volume

```bash
docker run -it --name container2 -v /my_storage alpine /bin/sh
```

## 2. Bind Mount

```bash
mkdir /home/aadmin/my_data
```

**Method 1:**
```bash
docker run -it --name container3 -v /home/aadmin/my_data/:/opt/data alpine /bin/sh
```

**Method 2:**
```bash
docker run -it --mount type=bind,source=/home/aadmin/my_data/,destination=/opt/data alpine /bin/sh
```

## 3. tmpfs

**Method 1:**
```bash
docker run -d -it --name tmptest1 --mount type=tmpfs,destination=/app alpine /bin/sh
```

**Method 2:**
```bash
docker run -d -it --name tmptest2 --tmpfs /app alpine /bin/sh
```

## Bind Mount Application Example

```bash
docker run --name mynode1 -p 8000:8000 -d -v /root/docker/lect-10/src/:/app/src node_app
```
